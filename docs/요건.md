# 배경
최근 바이브코딩이 대세로 자리잡으면서, 개발된 시스템이 어떤 동작을 할 때, 어떤 로직과 흐름을 타고 진행되는지 파악이 쉽지 않고,어떤 기능들과 메서드들이 생성되었는지도 확인이 쉽지 않다. 
이를 해결하기 위해, LLM이 개발을 할 때에, 개발하는 메서드들이 어떤 메서드고, 로직이 어떻게 흘러가는지 주석 설명을 항상 달고 개발이 진행되도록 합니다. 이때는 코드 구조나 문법에 대한 설명이 아닌 비즈니스 로직 관점으로 작성되도록 합니다.
    - BAD : plus_count를 호출합니다.
    - GOOD : 재고 수량을 추가합니다.


이 제품을 해당 개발하는 프로젝트에 이식시키면 (init) 개발된게 없을 때는 룰을 셋팅하고, 개발 된 것이 있을 때엔 룰 셋팅 및 이미 개발된 것들에 대해 룰에 맞춰 셋팅이 되도록 합니다.
그리고, 이 제품이 설치된프로젝트를 실행시키면, UI를 통해 시스템이 동작을 할 때에 어떤 흐름으로 동작했는지, 파라미터 및 엔티티 같은 것은 어떻게 전달되었는지 시각적으로 모니터링할 수 있고, 메서드들을 눌러서 주석에 작성된 설명들을 확인할 수 있습니다. 
그리고 메서드들간의 관계도도 파악이 되고, 엔티티 또한 사용처와 관계도 들을 시각적으로 파악이 가능해야합니다. 
모든 언어에 구애받지 않았으면 좋겠지만 어렵다면 우선 타겟은 1순위 python과 2순위 typeScript 3순위 SpringBoot 입니다.
그리고, 이 제품을 설치했을 때, 이왕이면 코드를 오염시키지 않고, log4java처럼 설치하면 자동으로 붙을 수 있게 AOP같은 느낌으로 동작하면 좋을 것 같습니다. 

즉, 이 제품이 설치된 후엔 LLM이 개발을 할 때에, 주석 설명을 룰에 맞춰 달고, 관계도같은 것의 현행화를 할 수는 있지만 코드에 직접 langfuse처럼 모니터링을 위한 코드를 남기고 싶지는 않습니다. 

이왕이면 추가 자원같은 것을 설치할 필요 없이 사용할 수 있으면 좋을 듯 합니다. 이게 어렵다면 최대 RDB / 관계도에 좋다면 GraphDB까지만 허용합니다.
